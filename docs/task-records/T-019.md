| 实现摘要 | **移动**：固定的地点连接图（山门—练功场—大殿；练功场—藏经阁），每次消耗 3 体力，只能去相邻地点；走 `POST /actions`（`kind: move`），有幂等、审计、日志。**任务**：静态定义 + 状态机 `locked→available→active→completed|failed`（终态不可再变，步数只增不减，奖励只能领一次，均在存档层与数据库约束两层把关）；条件只看服务端已保存的事实（已相识、所在地点、修炼进度、境界），按顺序推进，每次行动/见面/放置修炼结算之后评估，接取时立即评估；完成后自动解锁后续任务；接取/领取/放弃走 `POST /actions`（`kind: quest`），领取时货币、物品、NPC 反应与领取标记在同一事务提交。「承诺追踪」：NPC 发布的任务就是对玩家的承诺，条件满足并领取时兑现，全程留审计。新手任务链两条（初入山门、证明自己）。存档导出/导入包含任务并严格校验自洽性。 |
| 验证命令 | `npm run typecheck`；`npm test`；`npm run build`；`npm audit`；`PW_CHROMIUM_PATH=/opt/pw-browsers/chromium npx playwright test`；`npm run bench`；变异验证 ×3 |
| 结果与证据 | 类型检查 0 错误；Vitest 37 个文件 **928 项通过**；`npm audit` 0 漏洞；e2e **51/51**。覆盖：数据库约束（ID、状态、步数、接取/结束/领取时间与状态的一致性）；状态机全部非法流转被拒且状态不变；事务回滚；移动的 5 类拒绝与体力边界、性质测试（随机行走位置始终合法）；完整任务链（顺序推进、跳步无效、完成、解锁、领取）；奖励只发一次（同键重放与新键再领都不重复）；第二任务的进度与突破条件（失败的突破不算）；AI/自由输入无法宣布任务完成；通过自由行动打招呼推进任务；**随机序列 400 步×6 种子加入移动/任务/见面后，审计重放仍然恰好等于最终状态**，并断言覆盖到 `action.move`、`action.quest.accept`、`npc.met`、`npc.memory`、`quest.progress`；存档往返与 7 类内容非法、3 类格式非法；**带数据升级**：重建 `actions` 表后行动与审计事件的关联保持、唯一索引与新类型都在、外键开关已恢复。变异：领取不防重 → 4 条失败；步骤不按顺序 → 4 条失败；迁移不关外键 → 升级用例失败；均已还原。 |
| 发现并修复 | ① **重建表会静默丢失关联**：`actions.kind` 的 CHECK 约束要加新类型，SQLite 只能重建表。drizzle 生成的迁移用 `PRAGMA foreign_keys=OFF`，但迁移在事务里执行，这条语句无效；若外键开启，DROP 旧表会触发 `audit_events.action_id` 的 ON DELETE SET NULL，所有审计事件与行动的关联被清空。已用测试**复现这个问题**（对照组直接用迁移器升级，关联变成 NULL），然后让 `runMigrations` 按 SQLite 官方流程在事务**之外**关闭外键、迁移后恢复并用 `foreign_key_check` 校验。② 随机序列测试抓到一条过时的不变量（「丹药不可能凭空增加」），现在任务奖励会合法发放丹药，已改为「初始 + 已领取的任务奖励」。③ 我的一条测试直接改库造成状态，绕过了评估时机；改为与真实流程一致。 |
