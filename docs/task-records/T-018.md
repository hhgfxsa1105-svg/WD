| 实现摘要 | 表 `npc_memories`（事件记忆必须引用已记录的审计事件：外键 RESTRICT；只有合并摘要没有事件；类型、摘要长度、重要性、条数均有 CHECK）。记忆只由服务端按模板从事件生成：初次相识（重要性 6）、目睹突破成功（6）、目睹突破失败（3），同时按规则表微调 NPC 对玩家的关系；见证者是与玩家同地点且状态正常的 NPC。记忆与关系的变化记在单独的后果事件 `npc.memory`，使每个审计事件的差异恰好覆盖它自己造成的变化（审计重放测试保持通过）。每个 NPC 超过 30 条时，在同一事务里把最旧的低重要性（≤5）记忆合并为摘要，重要记忆永不合并或删除。检索 `selectMemories`：重要性优先、近期加成、条数与字数预算、时间正序。接口只读。导出带记忆，导入时合并为每 NPC 一条摘要。第一次与在场 NPC 打招呼留下记忆（`npc.met` 事件与玩家日志），再次打招呼不改状态。 |

| 结果与证据 | 类型检查 0 错误；Vitest 34 个文件 **831 项通过**；`npm audit` 0 漏洞；e2e **51/51**。覆盖：数据库约束（类型、事件规则、摘要长度、重要性、外键、被引用事件不可删、级联）；写入校验（未知 NPC、不存在的事件、`summary` 不能当事件类型、摘要与重要性越界）；合并（总条数受控、**原始条数守恒、重要记忆一条不丢**，含 20 组×300 次随机序列）；只有重要记忆时不丢；事务回滚连同合并一并撤销；突破成功/失败的记忆引用的正是那次突破的审计事件；不在场、休息、外出的 NPC 不会记住；多人在场各留一条；同键重试与被拒绝的行动不产生记忆；后果事件写入失败时整个突破回滚；初次见面只生效一次，大量记忆合并后「已相识」仍成立；接口只读（POST/PUT/PATCH/DELETE 全 404）、`context=1` 受条数与字数限制；**AI 无法写记忆**（注入式输入不产生任何记忆）；存档导出/导入往返（合并为摘要并替换原有记忆）。变异：内存存档不校验事件存在 → 1 条失败；见证者不看地点 → 4 条失败；不执行合并 → 1 条失败；均已还原。 |
| 发现并修复 | ① **审计重放与记忆的循环依赖**：记忆需要引用已落库的事件，而事件要先带上自己的差异——若把记忆写在原事件之后，原事件的差异就漏掉了关系与记忆变化。改为「原事件 → 后果事件 `npc.memory`」两步，每个事件的差异都恰好覆盖自己造成的变化。② **「已相识」会被合并掉**：若初次相识是低重要性，会被合并进摘要，导致重复「初次相识」；改为重要性 6（永不合并），并用测试锁定。③ **新的 zod 漏洞**：跑审计时出现 zod 高危漏洞（oversized constrained collections 耗尽内存，影响 zod 4.6.6 以下全部版本）。我们的输入本来就有体积上限（请求体 16KB、模型原文 8000 字），实际暴露面很小，但审计门槛是 0 漏洞，所以升级到 zod 4.6.7：只需适配 `z.record` 的两个参数与 `parseWith` 的类型，全部测试与端到端无回归；代价是前端包增大（见 K-30）。④ 我写的两条测试名不副实（标着并发其实是顺序；一条审计用例没有真正检查事件），已改写为真正的检查。 |
