# 1. 任务执行规则

- 每次只实现一个可验证的垂直切片或小任务组。

- 任务开始前确认输入、输出、依赖与验收标准。

- 完成后执行相关测试，并在任务记录中附命令、结果和缺陷。

- 未通过验收的任务不得标记完成；不得以跳过测试代替修复。

- 数据库变更、规则变更和安全相关变更需额外审查。

# 3. 优先级定义

| **优先级** | **含义**                   | **处理规则**                 |
|------------|----------------------------|------------------------------|
| P0         | 核心、数据、安全或发布阻断 | 必须完成后才能通过阶段门槛   |
| P1         | 主要体验或可靠性要求       | 原则上需在本阶段验收前完成   |
| P2         | 扩展或优化项               | 允许按计划后移，但须记录影响 |

# 4. 阶段门槛

| **阶段** | **必须提交的证据**                  | **通过条件**               |
|----------|-------------------------------------|----------------------------|
| S1       | 启动说明、演示步骤、基础测试        | 新环境可启动并完成原型循环 |
| S2       | 规则测试、离线结算测试、幂等测试    | 无重复奖励，状态结算正确   |
| S3       | AI 合约测试、故障降级测试、调用日志 | AI 不可越权，失败可恢复    |
| S4       | NPC 记忆与任务回归报告              | 关键人物状态和历史一致     |
| S5       | 世界事件和时间推进测试              | 事件可追溯且不会重复结算   |
| S6       | 安全报告、恢复记录、发布回归报告    | P0/P1 清零，发布流程可复现 |
