## 2. 本阶段检查项

| 编号 | 检查项 | 判定 | 证据 |
|---|---|---|---|
| C-01 | 结构化输出 | 通过 | `AiActionPlanSchema` 严格校验；`parseAiPlan` 宽容规范化且永不抛出；格式不合格最多重试 1 次；`ai-plan.test.ts`、`free-action.test.ts`；300 个随机模型输出下状态码只会是 200/422/503；`ai-degradation.test.ts` 含原型污染、1MB 载荷、越权字段 |
| C-02 | 实体引用 | 通过 | `checkPlanTarget` + `EntityCatalog`：未知物品/地点/人物进入澄清，不执行；非突破丹药、背包没有的丹药由服务端拒绝（`free-action.test.ts` 9 类澄清、丹药场景） |
| C-03 | 无直接写库 | 通过 | AI 层只返回文本；方案只是意图，映射到固定行动/突破/放置修炼后由服务端按**当前状态**重新判定；越权企图（加钱、改数值、夹带 requirements/currency）被丢弃，结果与普通修炼逐字段一致；叙事只能替换文字，状态、版本、丹药不变（对抗性叙事用例）；架构上 AI 模块只持有「调用记录」接口，不接触玩家状态存档；叙事回写由独立的叙事服务在事务内完成，且只替换文字 |
| C-04 | 提示注入防护 | 通过（模拟红队，未对真实模型验证） | 玩家原话只出现在**单独的用户消息**，系统提示恒等于固定文本（断言「所有调用的系统提示都等于 `buildSystemPrompt()`」）；11 种注入/畸形输入（忽略规则、伪造 JSON、控制字符与双向字符、围栏、SQL、路径、模板片段、环境变量……）均 200/400/422、状态不变；叙事提示不含玩家原话也不含 AI 方案；叙事守卫拒绝数字/货币/系统指令/JSON/链接。**局限**：真实模型是否被注入未验证，但因服务端重新判定，成功注入的后果仍被限制在「做一次合法行动」 |
| C-05 | 结果与叙事分离 | 通过 | 结算先提交（`COMMITTED`），叙事后置；10 类叙事故障（超时、拒答、空返回、鉴权、5xx、空文本、含数值、夹带指令、JSON、过长）下行动只提交一次、丹药只扣一次、状态与关闭叙事时逐字段一致；同键重放与已完成行动的重试不调用 AI；并发重试合并为一次调用；SQLite 重启后待补叙事仍可补写；变异（守卫放行、重放触发叙事、叙事不检查状态）均被测试抓住 |
| C-06 | 调用失败降级 | 通过 | 11 类错误均有统一的中文提示（不含类型名、状态码、密钥、路径）；降级矩阵（AI 关闭/额度用尽/全部失败/半数失败）下固定行动、突破、放置修炼、读取接口、存档导出导入照常；自由行动只会成功、被规则拒绝或 503，503 时状态不变且不占幂等键；前端 e2e：故障时提示紧贴输入框、状态点变黄、输入保留、固定行动可用、恢复后可重发 |
| C-07 | 成本限额 | 通过 | 单次输入字符上限（超过不发出、不占额度）、输出 token 上限、每日调用上限（持久化、预占，并发不超限）；叙事另有独立日额度、输出上限与 8 秒超时，默认只对突破叙事；调用重试有上限与退避，尊重 `Retry-After`；`ai-gateway.test.ts`、`narrative.test.ts` |
| G-01 | 调用可观测 | **部分通过** | `ai_call_logs` 记录供应商、模型、状态、错误类型、延迟、重试次数、token 用量（不含提示词、回复全文、密钥），`/ai/status` 报告当日用量。**缺口**：解析调用未关联行动 ID（K-24）；没有查看调用记录的界面/接口（K-25） |
| G-02 | 普通挂机不调用 AI | 通过 | 放置修炼、结算、休息、修炼的数值全部由规则函数完成；默认叙事只对突破（`AI_NARRATE=important`），修炼/休息「直接 COMPLETED，不调用 AI」有用例；放置修炼服务不持有 AI 依赖 |
| G-03 | 超时控制 | 通过 | 供应商请求超时（默认 20 秒）与有限重试（默认 2 次）；叙事 8 秒超时，迟到内容丢弃；SQLite `busy_timeout = 5000`；服务端关闭使用 `forceCloseConnections`，避免连接悬挂 |
| D-01 | 状态权威 | 通过（S3 范围） | 数据库状态优先：叙事不能改状态；AI 文本经守卫后才入库，且与成败矛盾的文本被弃用；NPC 与世界状态尚未实现，S4/S5 复审 |
| F-01 | 密钥保护 | 通过 | 密钥只来自环境变量；适配器与网关的错误信息、调用记录、`/ai/status`、前端构建产物均不含密钥；供应商回显密钥与路径时，玩家看到的仍是固定提示（`ai-degradation.test.ts`）；`.env` 被忽略 |
| F-05 | 日志最小化 | 通过 | 审计事件只记变化的游戏字段；`ai_call_logs` 只含元数据；玩家自由文本不写入审计事件，也不写入调用记录 |
| F-02 | 输入校验 | 通过 | 自由行动：200 字上限、严格 schema 拒绝多余字段/错误类型/非法幂等键；请求体上限 16KB；叙事重试的行动 ID 走路径参数查库，不存在返回 404 |
| 前端 | 自由输入与叙事重试界面 | 通过 | 设计稿先经确认；e2e 13 条（正常、快捷短句不直接发送、澄清保留输入、双击只发一个请求、网络中断复用幂等键、叙事待补与重试、AI 故障、次数用完、未开启、三种宽度布局）；手机 320/390、桌面 1280、深浅色截图见 `docs/task-records/T-016/` |

## 6. 过程中发现并修复的缺陷（供复盘）
| 缺陷 | 如何发现 | 修复 |
|---|---|---|
| 新增 `ActionResponse.ai` 字段后，T-010 时期存入数据库的行动响应读取失败，旧存档的幂等回放会校验不过 | 全链路测试与旧记录改写用例 | 读取时补默认值，并用 SQLite 真实改写旧记录的用例锁定 |
| 320 宽下输入框的默认宽度撑开面板网格列，「行动」按钮被挤出屏幕；原布局用例只查页面不查面板内部 | 手机截图目视复核 | 网格列固定为 `minmax(0, 1fr)`，新增面板内部溢出断言并确认其能抓住旧样式 |
| AI 故障提示显示在面板底部，被导航遮住 | 截图目视复核 | 提示紧贴输入框 |
| 服务端关闭偶尔卡住（约三分之一的 e2e 运行）：关闭时正在收发的连接变空闲后无人关闭 | e2e 清理阶段超时 | `forceCloseConnections`；之后连续多次运行无复发 |
| 我的测试假设有误：错误响应字段、校验状态码（400 而非 422）、半数失败时叙事可能待补 | 首次运行失败 | 按真实约定修正断言，非产品缺陷 |
