## 2. 本阶段检查项

| 编号 | 检查项 | 判定 | 证据 |
|---|---|---|---|
| B-02 | 奖励幂等 | 通过 | 任务奖励只能领取一次：存档层 `markQuestClaimed` 与数据库 CHECK 双重把关；同键重放返回同一结果、新键再领被拒绝（单元、接口、真实 HTTP 三处验证）；变异（去掉防重）→ 4 条测试失败 |
| B-03 | 前置条件 | 通过 | 移动：不相邻、原地、未知地点、体力不足（边界 3/2）均被拒绝且状态不变；任务：锁定的不能接取、未完成不能领取、未接取不能放弃、不能重复接取；步骤按顺序推进，后面的条件成立也不能跳过 |
| C-02 | 实体引用 | 通过 | 交谈目标必须是定义里存在的 NPC（编造的 ID、把显示名当 ID、`constructor` 等原型链名字均被拒绝）；提示词只列出真实 ID；任务、物品、地点同理 |
| C-03 | 无直接写库 | 通过 | 没有任何接口接受记忆文字或任务进度（`/memories`、`/quests`、`/relation` 只读，写方法 404）；自由输入里「记住……」「把任务设为 completed」「我已经完成任务了」均不产生记忆、不推进任务（测试覆盖） |
| D-01 | 状态权威 | 通过 | 关系数值只能经规则函数改变（单次每项 ±20，夹在合法范围）；任务条件只看服务端已保存的事实；记忆摘要来自模板 |
| D-02 | NPC 记忆来源 | 通过 | 事件记忆必须引用已记录的审计事件（外键 RESTRICT，被引用的事件不能删除）；只有合并摘要没有事件；突破的记忆引用的正是那次突破的审计事件（测试逐条核对）；真实 HTTP 抽样：苏晚晴的记忆「你与苏晚晴初次相识。」对应 `npc.met` 事件 |
| D-03 | 关系范围 | 通过 | 好感 −100..100、信任与敌意 0..100，方向固定为 NPC → 对象，不得指向自己；规则函数、契约、数据库 CHECK 三层一致；性质测试 200 组 × 50 步（含 NaN、Infinity、小数）数值始终合法、单步变化 ≤ 20；3000 步长期游玩后仍在范围内 |
| D-04 | 任务状态机 | 通过 | 状态机 `locked→available→active→completed|failed`，终态不可再变，步数只增不减，领取标记只对 completed 成立；全部非法流转有拒绝用例；导入存档时校验状态、步数与领取标记自洽、前置任务已完成；完整任务链的回归剧本 |
| D-05 | 事件去重 | 后续阶段 | 世界事件（定时调度）在 S5 才有；S4 内的「初次相识」只生效一次（含并发提交、记忆合并后、存档导入后） |
| D-06 | 时间一致性 | 后续阶段 | S4 的规则不依赖时间推进；NPC 日程与定时事件在 S5 |
| D-07 | 历史可追溯 | 通过 | 记忆与关系变化记在 `npc.memory` 后果事件，任务进度在 `quest.progress`，奖励在 `action.quest.claim`，导入在 `save.import` / `save.state`；**每个事件的前后差异恰好覆盖它自己造成的变化**：随机序列（400 步 × 6 种子，混入移动、任务、见面）按序重放全部差异恰好得到最终状态，并断言覆盖到全部新事件类型；**关系来源接口**把任何关系数值还原为「初始值 + 每次变化」并自检，有未被审计的改动时确实报告不一致（测试专门构造）；3000 步后全部关系数值可解释 |
| E-01 | 事务完整性 | 通过 | 记忆（含合并）、关系、任务、奖励、审计在同一事务；任一环节失败整体回滚（记忆写入、突破、领取、存档导入各有用例；导入写到一半由数据库触发器制造故障，玩家、世界、审计全部回滚，故障解除后可重新导入） |

## 6. 过程中发现并修复的缺陷（供复盘）
| 缺陷 | 如何发现 | 修复 |
|---|---|---|
| 重建 `actions` 表的迁移会让所有审计事件的 `action_id` 被外键动作置空（drizzle 生成的 `PRAGMA foreign_keys=OFF` 在事务内无效） | 评估迁移方案时推演，并写测试复现（对照组关联确实变空） | `runMigrations` 在事务外关闭外键、迁移后恢复并校验 |
| 审计重放与记忆的循环依赖：记忆要引用已落库的事件，原事件的差异漏掉后果 | 设计阶段推演 | 「原事件 → 后果事件 `npc.memory`」，每个事件的差异覆盖自己造成的变化 |
| 「已相识」依赖的「初次相识」记忆会被合并掉，导致重复见面 | 设计推演并用测试锁定 | 初次相识重要性 6（永不合并）；导入存档时记忆原样保留（K-29 关闭） |
| **存量缺陷：存档导出/导入从未带背包**（自 T-008） | 存档回归测试第一次运行 | 存档带物品与数量，导入整体替换，旧文件不改动背包，并校验 |
| 导入存档曾在审计里留下无法解释的状态跳变，且分步写入中途失败会留下半个存档 | 可解释性自检的设计推演 | 整体事务；`save.import` / `save.state` 事件 |
| 新公布的 zod 高危漏洞（影响 4.6.6 以下全部版本） | 例行 `npm audit` | 升级 zod 4.6.7，适配两处 API，无回归；前端包增大（K-30） |
| 随机序列测试里的过时不变量「丹药不会凭空增加」 | 随机序列失败 | 改为「初始 + 已领取任务奖励」 |
| 关键词模拟不识别「打招呼」 | 真实 HTTP 验收 | 补充识别词与测试（只影响本地模拟模型，不影响产品逻辑） |
| 我写的若干测试假设或统计有误（测试名与实际不符、测试数量写错、直接改库绕过评估时机） | 复核与运行失败 | 已改写或更正，均非产品缺陷 |
