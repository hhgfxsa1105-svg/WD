## 6. 过程中发现并修复的缺陷（供复盘）
| 缺陷 | 如何发现 | 修复 |
|---|---|---|
| 迁移 SQL 读取旧表不存在的列，空库与旧存档都会失败（drizzle-kit 默认生成） | 变异验证（还原默认 SQL 时测试失败）与「带数据升级」测试 | 手工修正并加测试 |
| 放置修炼「整片取整」让频繁轮询者永远拿不到收益 | 性质测试：每分钟结算 600 次应等于一次结算 | 只消耗产出收益所需的时间片，零头保留 |
| 离线结算保留的零头在下次在线结算时按 100% 重新计价 | 「超长离线反复领取」「离线封顶后立即再领取」用例 | 离线结算不保留零头 |
| 开始放置修炼误提示「暂无可领取的收益」 | 截图目视复核 | 仅手动领取才提示，并加断言 |
