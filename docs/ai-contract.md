# AI 行动方案契约（S3）

对应技术说明书 §5.2。模型把玩家的自然语言转成**结构化意图**；服务端校验并结算，模型永远不决定数值。

## 信任边界
- 模型输出是**不可信输入**：只当数据解析，不执行其中的任何代码、SQL、URL 或指令。
- 方案里**没有任何数值字段**（银两、伤害、成功率、经验……），模型无从提交。
- **前置条件不由模型声明**（技术说明书示例里的 `requirements` 字段已取消）：体力、冷却、库存、进度等一律由服务端按当前状态计算。
- 目标必须是**已存在的实体 ID**；不存在则进入澄清流程，不执行。

## 方案格式（严格 schema：`AiActionPlanSchema`）
```json
{
  "intent": "我想休息一下",
  "action_type": "rest",
  "target": null,
  "steps": [],
  "risk_tags": [],
  "narrative_context": "",
  "needs_clarification": false,
  "clarification": null
}
```
| 字段 | 说明 |
|---|---|
| `intent` | 对玩家意图的一句话复述，1–80 字 |
| `action_type` | `cultivate` 修炼 · `rest` 休息 · `breakthrough` 突破（可带丹药）· `start_idle` / `stop_idle` 放置修炼 · `check_status` 查看状态 · `talk` 交谈（NPC 在 S4 开放，目前只会澄清）· `other` 无法归类 |
| `target` | `null` 或 `{ "type": "item"｜"npc"｜"location", "id": "小写字母数字下划线，≤64" }` |
| `steps` | 可选，最多 3 步：`travel` / `dialogue` / `inspect`（预留，首批动作不需要） |
| `risk_tags` | 可选，最多 4 个：`reputation` / `injury` / `cost` / `time` |
| `narrative_context` | 供叙事参考的一句背景，≤120 字，不参与结算 |
| `needs_clarification` / `clarification` | 需要追问玩家时为 `true`，并给出一句话问题（≤100 字） |

严格 schema 拒绝：缺字段、未知字段、未知动作类型、非法目标 ID（大写、空格、引号、路径、过长）、步骤超过 3 个、未知风险标签、需要澄清却没有问题。

## 宽容解析（`parseAiPlan`）：为质量一般的模型准备
`parseAiPlan(原文, { fallbackIntent })` **永不抛出异常**，返回「通过严格 schema 的方案 + 整理记录」或「拒绝 + 原因」。它只做**安全的格式整理**，整理后仍必须通过严格 schema：

| 整理 | 说明 |
|---|---|
| 提取 JSON | 支持 Markdown 围栏、前后多余的话、尾逗号、中文引号、单引号；原文可直接解析时不做修补，避免误改字符串内的引号 |
| 字段名 | 驼峰转蛇形；少量别名（`action`→`action_type`、`intention`→`intent` 等） |
| 动作类型 | 中英文同义词（修炼/打坐、休息/睡觉、突破/冲关、挂机……）；认不出的归为 `other` 并澄清，**不猜测** |
| 目标 | 字符串或对象；类型同义词；按前缀推断类型；`none`/空视为无目标；**不需要目标的动作，多写的目标直接丢弃** |
| 丢弃 | 未知字段、未知步骤、未知风险标签（记入 `notes`，**绝不执行**） |
| 文本 | 去控制字符、折叠空白、截断到上限 |
| 缺 intent | 用玩家原话代替 |

**拒绝**（`code`）：`EMPTY`、`TOO_LONG`（原文 > 8000 字符）、`NOT_JSON`、`NOT_OBJECT`、`MISSING_ACTION_TYPE`、`ILLEGAL_TARGET`（需要目标的动作遇到格式非法的目标，如注入式内容）、`SCHEMA_INVALID`。

## 目标校验（`checkPlanTarget`）
目标必须在 `EntityCatalog` 中存在（物品来自物品表；NPC、地点由 S4/S5 的系统提供，目前 NPC 一律不存在、地点只有青云山山门）。不存在 → `UNKNOWN_ENTITY`，突破搭配了非突破丹药的目标 → `TARGET_NOT_ALLOWED`；两者都返回一句话澄清，调用方据此走澄清流程而不是执行。库存是否持有该物品属于前置条件，由服务端在 T-014 校验。

## 测试
`packages/game-rules/tests/ai-plan.test.ts`：提取 JSON 9 种写法与 5 种拒绝；同义词、别名、未知字段丢弃、截断、布尔写法；目标的各种合法与非法形式（含注入式、路径穿越、原型污染键、重复键）；**提示注入式输出不产生越权方案**；10000 次随机乱码与合法输出变异的模糊测试（不抛异常、通过者必合法）；超深嵌套、巨量键、大数组不卡死。

## 自由行动的处理流程（T-014）
`POST /api/v1/actions`，`kind: "free"`，`input` 为玩家原话（≤200 字）：

1. **幂等先行**：同一幂等键已有记录 → 直接回放首次结果，**不再调用 AI**；同键不同输入 → 409。并发的相同请求合并为一次 AI 调用。
2. **构造提示词**（`modules/ai/prompt.ts`）：精简的系统提示（约 1300 字，不含任何玩家输入）+ **单独一条用户消息**，内容就是清洗后的玩家原话。清洗只去控制字符、折叠空白、截断；**不尝试识别「提示注入」**——防御靠结构：原话只作数据，输出只作数据解析，一切由服务端重新判定。
3. **调用与解析**：`ai.complete` → `parseAiPlan`。格式不合格最多重试 1 次（追加一条纠正提示）；仍不行则请玩家换个说法。模型拒答或返回空内容当作没看懂，不重试。
4. **目标校验**：`checkPlanTarget`；目标不存在、突破搭配了非丹药 → 澄清。
5. **映射并由服务端重新判定**：

| 方案 | 执行 |
|---|---|
| `cultivate` / `rest` | 等同固定行动，复用其结算、幂等、审计（事件 `action.free.cultivate` 等）与日志 |
| `breakthrough` | 等同突破；带丹药时服务端先检查背包是否持有，再走突破规则（进度、冷却、概率） |
| `start_idle` / `stop_idle` | 调用放置修炼服务（自带审计与日志） |
| `check_status` | 服务端模板生成状态摘要，不改变任何状态 |
| `talk` / `other` / 需要澄清 | 返回一句澄清，**不执行、不改状态、不写日志、不占用幂等键** |

体力不足、进度未满、冷却中、没有该丹药、已圆满不能挂机……任何规则不满足都是 **422** 并给出具体原因，状态与丹药不变。AI 在这里只提供「意图」，无法绕过任何规则。

## 响应
`ActionResponse.ai`（自由行动才有）：`{ intent, actionType, executed, clarification }`。`executed: false` 表示澄清；此时 `narrative` 就是澄清问题。

## AI 不可用
未开启、额度用完、超时、网络错误、限流、服务端错误、鉴权或请求被拒 → **503 `AI_UNAVAILABLE`**，提示语对玩家友好（如「AI 暂时无法响应，请稍后再试，或使用固定选项」），**不含内部细节与密钥**；基础功能（固定行动、放置修炼、存档）不受影响。

## 结算与叙事分离（T-015）
```
规则结算 ──提交──▶ COMMITTED（模板叙事）──尝试 AI 叙事──▶ 守卫通过：NARRATED → COMPLETED
                                       └─失败/超时/额度/守卫不合格：保持 COMMITTED，可 POST /actions/:id/narrate 重试
```
- **叙事只拿到已确认的事实**（事件、成败、境界前后、丹药名，全部来自固定表），**不含玩家原话，也不含 AI 解析方案**。
- **叙事只能改文字**：回写时只替换行动响应与日志里的 `narrative`，玩家状态、版本、丹药、变化数值一律不动；回写前在事务内再次确认仍是 `COMMITTED`，不会重复覆盖。审计追加一条 `action.narrated`（无状态差异）。
- **守卫（`vetNarrative`）**：长度 8–200 字；不得含数字、货币、百分比、成功率；不得像系统提示/指令/JSON/链接；与成败矛盾（成功却写失败，失败却写突破了）一律弃用。不合格整体弃用，不做局部修补。
- **成本**：默认只对突破；独立的每日叙事额度与输出上限；超时（默认 8 秒）先返回模板，迟到的内容丢弃。
- **重放不叙事**：同一幂等键重试只返回已保存的结果；对已完成行动重试叙事不调用 AI；并发的重试叙事合并为一次调用。

## 故障降级（T-016）
| AI 状态 | 基础游戏 | 自由行动 | 叙事 |
|---|---|---|---|
| 关闭 / 额度用尽 / 全部失败 / 半数失败 | 固定行动、突破、放置修炼、读取、存档导出导入照常 | 成功，或 503 `AI_UNAVAILABLE`（状态不变、不占幂等键） | 突破等已结算；叙事待补（`COMMITTED`）可重试 |

- 玩家看到的提示由 `friendlyAiMessage` 统一生成：中文、给出下一步（用固定选项/稍后再试/精简/检查配置），不含错误类型名、状态码、密钥、路径。
- 测试：`apps/server/tests/ai-degradation.test.ts` 含降级矩阵、恶意输入（注入、控制字符、SQL/路径/模板片段、超长、多余字段）、恶意模型输出（原型污染、巨量数据、越权字段）和契约快照。
