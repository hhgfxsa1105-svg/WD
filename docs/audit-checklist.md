# 1. 审计记录规则

- 检查结果必须基于实际执行的测试、代码审查或运行证据，不以口头声明代替。

- 失败项记录严重级别、复现步骤、责任模块、修复任务和复测证据。

- 涉及安全、存档、资源、权限或世界状态的检查不得随意标记为不适用。

- 发布前所有 P0/P1 项必须通过；未解决项必须阻止发布。

- 审计报告记录代码版本/提交号、环境、执行日期和审计人员。

# 5. 发布签核规则

- 任何 P0/P1 失败项都阻止发布。

- P2/P3 可在风险评估后延期，但必须有负责人、计划和影响说明。

- 未执行的测试不得标记为通过。

- 发布结论必须包含版本、提交号、环境、测试结果及已知限制。
